# Music sync (rclone) and MPD configuration

How the music library gets from Google Drive onto disk and into MPD, which files
are generated vs. version-controlled, and how to change any of it safely.

Read when touching a music sync profile, changing where the library lives,
regenerating `mpd.conf`, or debugging a sync that ran but changed nothing.

---

## 1. The four layers

| layer | lives at | owned by |
|---|---|---|
| **Backends** | `~/.config/rclone/rclone.conf` | assembled by `rclc` from GPG-encrypted fragments in the `_secured` submodule — never edited directly |
| **Profiles** | `~/.config/rclone-sync-profiles/<name>.conf` | dotfiles (stowed) |
| **Engine** | `/usr/local/bin/rclone-sync.sh` | `linux-system-manager/services/rclone-sync.sh`, copied there by `sudo ./install.py` |
| **Scheduler** | systemd timers | see §4 — currently two competing mechanisms |

A profile is the unit of configuration. `rclone-sync.sh <profile-name>` reads
`~/.config/rclone-sync-profiles/<name>.conf` and does the whole job:

```sh
REMOTE="gdrive"                 # backend name from rclone.conf
REMOTE_PATH="Media/Music"       # path within the backend
LOCAL_PATH="/home/susamn/Music/susamn-music-collection"
SYNC_TYPE="one"                 # one → rclone sync · bidirectional → rclone bisync
DIRECTION="remote-to-local"     # only meaningful when SYNC_TYPE=one
SCHEDULE="*:0/30"               # consumed by install.py, NOT by the user timers
RCLONE_OPTS="--exclude=*.m3u8"
```

`REMOTE`, `LOCAL_PATH`, and `SYNC_TYPE` are required; the engine exits if any is
missing. `SYNC_TYPE="one"` means **`rclone sync`, which deletes at the
destination** to make it match the source — with `remote-to-local` the local
directory is disposable and the remote wins.

## 2. `mpd.conf` is generated — do not edit it

This is the same trap as `~/.claude/CLAUDE.md`: the file you would naturally edit
is a build artifact that gets overwritten.

```
dotfiles/.config/mpd/mpd.conf.bak   ← TEMPLATE. version-controlled, stowed. Edit THIS.
            │
            │  mpdc configure   (workspace/scripts/mpd-configurer.sh)
            │  patches only music_directory + playlist_directory
            ▼
~/.config/mpd/mpd.conf              ← GENERATED. real file, not stowed, not tracked.
```

`mpdc configure` prompts (fzf, or typed) for a **tracks** profile and a
**playlists** profile, reads `LOCAL_PATH` from each, and rewrites exactly two
lines in the template:

- `music_directory`  ← tracks profile's `LOCAL_PATH`
- `playlist_directory` ← playlists profile's `LOCAL_PATH`

Everything else in `mpd.conf.bak` is passed through untouched. It also creates
both directories and `~/.local/share/mpd/` if missing.

**Consequence:** the profile's `LOCAL_PATH` is the single source of truth for
where music lives. Changing it in a profile and not re-running `mpdc configure`
leaves MPD pointed at the old directory, with no error from either side.

## 3. Changing where the library lives

1. Edit `LOCAL_PATH` in `~/dotfiles/.config/rclone-sync-profiles/<profile>.conf`.
2. `mpdc configure` — re-pick the same two profiles; regenerates `mpd.conf`.
3. `mpdc restart` — MPD re-reads config and, with `auto_update "yes"`, rescans.
4. Verify: `mpdc stats`, `mpdc playlists`.

To change anything *other* than the two directories (outputs, replaygain,
buffers), edit `mpd.conf.bak` and then run `mpdc configure` — editing
`mpd.conf` directly works until the next regeneration silently discards it.

## 4. Known issue: two schedulers are running the same syncs

Both mechanisms are currently live for `music-playlists` and `music-tracks`, and
they invoke the **identical** command as the same user against the same profile:

| | system scope | user scope |
|---|---|---|
| unit | `rclone-sync@<profile>.timer` | `music-<name>.timer` |
| source | generated by `install.py` from the profile's `SCHEDULE`, via a `.timer.d/override.conf` drop-in | hand-written in `dotfiles/.config/systemd/user/` |
| cadence | `OnCalendar=*:0/3` / `*:0/30` | `OnUnitActiveSec=3min` / `30min` |
| profile selection | instance name (`%i`) | `EnvironmentFile=%h/.config/music-sync/<name>.env` → `MUSIC_SYNC_PROFILE` |
| ExecStart | `/usr/local/bin/rclone-sync.sh %i` | `/usr/local/bin/rclone-sync.sh ${MUSIC_SYNC_PROFILE}` |

So each library syncs twice per interval, with two `rclone sync` processes able
to overlap on the same destination directory. Pick one and disable the other:

```bash
# keep the generic system timers (SCHEDULE lives with the profile, one mechanism)
systemctl --user disable --now music-playlists.timer music-tracks.timer

# ...or keep the user timers (session-scoped, grouped under personal-services.target)
sudo systemctl disable --now rclone-sync@music-playlists.timer rclone-sync@music-tracks.timer
```

Note the `SCHEDULE` field is dead config if the user timers win — their cadence
is hardcoded in the `.timer` file, so the two would then disagree silently.

## 5. Known issue: the two music profiles overlap

`music-tracks` syncs `Media/Music`, which **contains** `music-playlists`'
`Media/Music/music-metadata/playlists`. The tracks profile excludes only
`*.m3u8`, not `*.m3u`, so playlists are pulled into the collection directory as
well: 642 `.m3u` files currently sit inside `music_directory` alongside the
audio, versus 215 in the actual `playlist_directory`.

If that is unintended, add `--exclude=/music-metadata/**` (or `--exclude=*.m3u`)
to the tracks profile's `RCLONE_OPTS`. Related: the playlists profile includes
`*.m3u` while `music-playlists.service`'s description says `m3u8` — one of the
two is wrong.

## 6. Management commands

| command | alias | does |
|---|---|---|
| `mpd-configurer.sh configure` | `mpdc configure` | regenerate `mpd.conf` from template + profiles |
| `mpd-configurer.sh start\|stop\|restart\|enable\|disable\|daemon-status` | `mpdc …` | manage the `mpd.service` **user** daemon |
| `mpd-configurer.sh tracks [term] \| playlists \| playlist <n> \| stats \| status` | `mpdc …` | query the library via `mpc` |
| `mpd-configurer.sh mpc -- <args>` | `mpdc mpc -- …` | raw `mpc` passthrough |
| `rclone-config-manager.sh` | `rclc` | assemble/split the GPG-encrypted rclone backends |
| `music-library-normalizer.py` | `mln` | normalize the on-disk library |
| `mpdtui` | `mtx` / `mt` / `mtp` / `mtt` | full / mini / playlist-search / track-search player |

Sync logs go to the journal under distinct identifiers:

```bash
journalctl --user -u music-playlists.service -n 50     # user timer path
journalctl -u rclone-sync@music-playlists.service -n 50  # system timer path
```

## 7. Adding a new synced music source

1. Create `~/dotfiles/.config/rclone-sync-profiles/<name>.conf` with the fields
   in §1. Use `DIRECTION="remote-to-local"` unless you intend local edits to
   propagate — `SYNC_TYPE="one"` deletes at the destination.
2. `./do-stow.sh` to link it into `~/.config/`.
3. Schedule it — one mechanism only (§4). For the system path, set `SCHEDULE`
   and re-run `sudo ./install.py` from `linux-system-manager`.
4. If MPD should use it, `mpdc configure` and pick it.
5. Attach any hand-written unit to `personal-services.target` — see
   `personal-systemd-services.md`.
